# UI Redesign — Modern Sports Management Presentation: Design

**Status:** Approved. A presentation-layer phase — it adds no gameplay, changes no simulation, and removes nothing.

## Goal

Replace the current 13-line `style.css` and bare-`innerHTML` markup with a real design system and app shell, so the game reads as a modern sports management title (Football Manager / NBA 2K MyNBA register) instead of an unstyled prototype.

**Preservation is the primary constraint, not a caveat.** Every existing function, event listener, `GameState` field, and gameplay mechanic survives unchanged. Exactly one behavioral change is in scope, explicitly requested: the `#sim-controls` listener-destruction bug in Section 8.

## 1. The Preservation Contract

All UI in this codebase is generated by JS. `index.html` is a four-`div` shell; every view's markup lives in `innerHTML` strings inside `ui/*.js`, with listeners attached immediately after render.

Auditing all 19 view files, every listener attaches by one of exactly three mechanisms:

| Mechanism | Examples |
|---|---|
| `document.getElementById(id)` | `#sim-next-game`, `#propose-trade-btn`, `#scouting-add-btn`, `#save-name-input` |
| `container.querySelectorAll('[data-*]')` | `th[data-key]`, `button[data-waive-id]`, `tr[data-game-id]`, `input[data-automation-key]` |
| tag/type/name selectors | `input[name="sim-engine"]`, `input[type="checkbox"][data-player-id]` |

This yields the contract every change in this design obeys:

- **Never** rename or remove an `id`, a `data-*` attribute, an `input[name]`, or an input `type`.
- **Never** change a render function's signature, arguments, or return value.
- **Only** add wrapper elements, class names, and text formatting *around* existing hooks.
- The listener block at the bottom of each view file is **not edited** — only the HTML-string block above it.

Extra nesting is transparent to every selector above, because all `querySelectorAll` calls are descendant selectors, never child (`>`) selectors.

**Test-suite safety:** `scripts/validate-*.js` are logic-only — grepping them for `ui/`, `innerHTML`, `document.`, and every render function name returns zero matches. No test asserts on markup, so markup edits cannot break the suite. Re-running all nine validators unchanged after the redesign is part of the verification in Section 10.

## 2. Three Structural Hazards

Found by reading the call sites, each resolved by design rather than by care:

**A. `#app-view` cannot carry the grid.** `script.js` sets `document.getElementById('app-view').style.display = 'block'` in three places (`spectateLeague`, `selectTeam`, `loadGame`). An inline `display: block` would clobber a CSS `display: grid` on that element.

*Resolution:* `#app-view` stays a plain block-level show/hide toggle. A **new inner `.app-shell` div** carries the grid. Zero JS change.

**B. `#sim-controls` receives an appended direct-child button.** `renderView` appends the offseason advance button (`#advance-offseason-btn` / `#advance-to-fa-btn` / `#start-new-season-btn`) directly into `#sim-controls`, *after* whatever `renderSimControls` built.

*Resolution:* the dock's own controls live inside `.dock-group` wrappers, so the appended button is the only **direct child button** of `#sim-controls`. CSS targets `#sim-controls > button` and styles it as the prominent advance CTA. It lands correctly placed by construction, with no JS coordination.

**C. `runWithDelay` disables buttons by container-wide query.** `container.querySelectorAll('button').forEach(b => b.disabled = true)` — a descendant selector, so buttons nested inside `.dock-group` wrappers are still found and still disabled during a sim. No change needed; noted so the nesting isn't mistaken for a risk.

## 3. Design Tokens

All tokens are CSS custom properties on `:root`. Nothing in the stylesheet hardcodes a color.

**Surfaces** — a four-step dark ramp, so panels read as layered rather than flat:

| Token | Value | Use |
|---|---|---|
| `--bg` | `#0B0E14` | app background |
| `--surface-1` | `#131822` | panels, tables |
| `--surface-2` | `#1A2029` | table headers, sidebar, dock |
| `--surface-3` | `#232B37` | hover, raised elements |
| `--line` | `#2A3340` | hairline borders |
| `--line-strong` | `#3A4553` | emphasized dividers |

**Text:** `--text #E6EAF0`, `--text-dim #93A1B5`, `--text-mute #64748B`.

**Semantic:** `--win #3FB950`, `--loss #F85149`, `--warn #D29922` (cap trouble, injuries), `--info #58A6FF`, `--gold #D4A94E` (elite ratings, championships, Hall of Fame).

**Geometry:** radii `4px / 8px / 12px`; one elevation shadow `0 2px 8px rgba(0,0,0,.4)`; spacing on a 4px scale.

## 4. Team Accent With a Contrast Guardrail

`--accent` and `--accent-soft` are set at runtime from the user's team colors, driving nav active states, focus rings, KPI tile borders, and header rules.

Naively using `team.colors.primary` fails on real data: Brooklyn is `#000000` and Toronto's secondary is `#000000` — invisible against `--bg`. So a pure helper `resolveAccent(team)` in `ui/topbar.js` applies relative luminance:

1. Use `colors.primary` if its luminance clears a minimum threshold against `--bg`.
2. Otherwise use `colors.secondary` if *it* clears the threshold.
3. Otherwise fall back to `--info` (`#58A6FF`).

The resolved value is written to `document.documentElement.style` as `--accent`. This is additive — it reads `TEAMS` data and writes only CSS variables, never game state.

## 5. Typography

System font stack. Two decisions carry most of the effect:

- **`font-variant-numeric: tabular-nums`** on every stat cell, KPI value, and rating chip. Columns of numbers align to a fixed grid instead of jittering — the highest-leverage single change for a stats-dense game.
- **Uppercase micro-caps** (`.7rem`, `letter-spacing: .08em`, `--text-dim`) for table headers, sidebar group labels, and panel titles. This is what produces the broadcast/front-office register.

Numeric table columns are right-aligned via a `.num` class applied where markup is rebuilt.

## 6. Component Inventory

Defined once in `style.css`, reused across all views:

1. `.app-shell` / `.app-sidebar` / `.app-main` — the grid shell
2. `.nav-group` / `.nav-item` — sidebar nav with a left accent bar on active
3. `.topbar` / `.status-chip` / `.cap-meter` — persistent status strip
4. `.sim-dock` / `.dock-group` — grouped sim controls
5. `.data-table` — sticky header, hover row, sort caret, tabular numerals
6. `.kpi-tile` — label / value / delta stat block
7. `.rating-chip` — OVR/POT tiered: 90+ gold, 80+ blue, 70+ green, 60+ neutral, below dim
8. `.pill` variants — position, W/L, contract years, scouted level, play mode
9. `.panel` / `.panel-header` — section container
10. `.btn` variants — primary / secondary / ghost / danger; bare `button` defaults to secondary so unedited markup still looks intentional
11. Dark form controls — `input`, `select`, `textarea`, `input[type=checkbox]`, `input[type=radio]`, `input[type=color]`
12. `.empty-state` — replaces the current bare "nothing yet" paragraphs
13. `.feed-item` — timeline row with day marker
14. `.team-card` — gradient from team colors, logo, hover lift
15. `.meter` — thin horizontal progress bar (cap usage, scouting confidence, chemistry)

Global: custom scrollbars, visible `:focus-visible` rings, and a `@media (prefers-reduced-motion: reduce)` block disabling transitions.

## 8. The `#sim-controls` Bug Fix

**The bug.** `renderView` (`script.js:253, 256, 267`) does:

```js
simControlsEl.innerHTML += '<button id="advance-offseason-btn">Advance to Offseason</button>';
```

`innerHTML +=` reads, concatenates, and re-assigns — destroying and recreating every child node, and with them every listener `renderSimControls` attached moments earlier. So whenever an offseason advance button is showing, all twelve sim controls are dead: Next Game, Next Day, Sim to End, the speed select, everything.

**The fix.** Replace `innerHTML +=` with `insertAdjacentHTML('beforeend', ...)` at all three sites. `insertAdjacentHTML` parses and inserts the new node *without* touching existing children, so their listeners survive.

```js
simControlsEl.insertAdjacentHTML('beforeend', '<button id="advance-offseason-btn">Advance to Offseason</button>');
```

Three one-line changes. The subsequent `getElementById(...).addEventListener(...)` lines are untouched and still resolve. This is the one intentional behavioral change in this phase, and it strictly restores intended function.

It also preserves Hazard B from Section 2: the appended button remains a direct child of `#sim-controls`, so the `#sim-controls > button` CTA styling still applies.

## 9. Per-View Changes

Nineteen files. In every case the edit is confined to the HTML-string construction; the listener-wiring block below it is untouched.

**New file — `ui/topbar.js`.** Exports `renderTopBar(container)`, reading `GameState` and `TEAMS` to render the team identity block and status chips (season year, day, record, payroll vs. cap with a `.cap-meter`, chemistry, play-mode pill). Also applies `resolveAccent` (Section 4). Renders an empty-safe placeholder before a team is selected. Wired by a single added line in `renderView()` and a `<script>` tag in `index.html`. It reads state and writes only DOM and CSS variables.

**Structural rebuilds:**

- `ui/nav.js` — `NAV_ITEMS` gains an additive `group` field (`Team` / `League` / `Transactions` / `System`); `renderNav` emits group headers and sets `btn.className = 'nav-item'` / `'nav-item active'`. Signature, item ids, commissioner filtering, and the `onNavigate` callback are unchanged.
- `ui/teamSelect.js` — play-mode radios become a segmented control (same `input[name="play-mode"]` values and `:checked` read), team grid becomes gradient cards with logo and conference caption, spectate becomes a primary CTA, save list gets its own panel.
- `ui/dashboard.js` — the `<p>` stack becomes a KPI tile grid (record, roster size, chemistry, fan/owner happiness), a cap panel with `.cap-meter` and over/under coloring, and a next-game card. No listeners exist in this file at all.
- `ui/simControls.js` — buttons wrap into `.dock-group`s: primary (Next Game / Next Day / Sim to End), targets (deadline / draft / FA), fast-forward (N seasons / championship / custom days), then speed select and `#sim-status`. Every id, the two number inputs, and the select options are unchanged. `#sim-status` gets a pulse indicator via `:not(:empty)`.
- `ui/roster.js` — rating chips for OVR/POT, position pills, `.num` on stat columns, salary formatted compactly, Waive/Scout as danger/ghost buttons, career table in its own panel. `th[data-key]`, the sort-caret text, and both `data-*-id` button attributes are unchanged.

**Panel and table treatment** (same pattern, view-specific detail): `standings` (conference columns, division panels, colored point differential), `schedule` (W/L pills, row hover affordance, box score in a panel), `liveFeed` (timeline), `awards`, `history` (five sections as panels), `saveLoad` (slot cards), `draft` + `draftPicker` (scouted-level pills, rating chips), `freeAgency` (+ bidding panel as a raised card), `scouting` (+ confidence meters, report card), `settings` (label rows → toggle rows), `tradeCenter` (participant panels, value/salary balance readout), `commissioner` (form sections as panels).

## 10. Verification

Presentation changes can't be verified by assertion, so verification is behavioral, per view:

1. Load each view in the browser; console must be clean.
2. Exercise the interactions that prove listeners survived: sort the roster table both directions, waive and scout a player, click a schedule row for its box score, toggle each settings checkbox and confirm `GameState` updates, add a team and a player to a trade and propose it, add a scouting target and spend points, save to and load from a slot.
3. Run the sim: Next Game, Next Day, Sim to End, a multi-season run — confirming the dock disables during simulation and `#sim-status` updates.
4. **Specifically verify the Section 8 fix:** advance to the offseason and confirm the sim control buttons still respond, which they do not today.
5. Re-run all nine `scripts/validate-*.js` — they must pass unchanged, confirming no logic was touched.

## Out of Scope

- Any change to simulation, ratings, contracts, trades, drafting, or progression logic.
- The two placeholder views (`salarycap`, `news`) stay placeholders — they get the styled empty state, not implementations.
- Responsive/mobile layout. Target is desktop, matching how the game is played.
- New gameplay features of any kind.
